Onboarding Guide

Skill Manager

Know what skills your AI agents have, where they live, and whether they drifted. Every skill is a living genome - a five-location strip that stays continuous when copies agree and visibly breaks when they drift. Health at a glance, one click to heal.

The dashboard with the DRIFT filter active - 14 skills whose copies disagree.

01Why you need it

AI agents are only as good as their skills - but skills rot silently. A fix lands in ~/.agents but not the repo. The same skill name hides two different versions. And nobody can answer "is my skill set up to date?" without spelunking five directories by hand.

Skill Manager makes the inventory visible, the drift detectable, and the "what does this actually do" question answerable in one click.

02Quick start

Clone the repo
git clone https://github.com/intelligentrascal/skill-manager.git && cd skill-manager
Install
npm install (zero runtime dependencies - Node built-ins only)
Run
npm run serve
Open
http://127.0.0.1:7788

That is the whole setup. No build step, no config file required - it scans your default skill locations automatically.

03The dashboard

The Skill Genome: every skill is a five-location strip (pi - opencode - claude - shared - repo). A continuous strip means your copies agree; a coral, cracked gene means drift. Click any genome for the specimen tray - the diff, the source, and one-click healing. A Mutation queue lists everything that needs attention.

Five things to know:

Stats strip - total skills, total copies, locations, and the health split (unique / duplicate / drift).
Search - filters by name and description as you type.
Harness chips - Pi, OpenCode, Claude, shared, repo. Click one to see only the skills that live there.
Status chips - OK / DUP / DRIFT. One click to isolate the skills that need attention.
Rows - name, description, which harnesses expose it, and its status badge.

Click any row to open the detail drawer: every copy with its location, sha256 and modified date, the description, tags, and the full SKILL.md source. For skills with a detected GitHub source, a Check upstream button compares your copy against the upstream and flags STALE or UP TO DATE. For drifted skills, an inline drift diff shows exactly which lines differ between the divergent copies.

The detail drawer - every copy, the description, and the full SKILL.md.

04The status model

The core concept. For each skill name, Skill Manager hashes every copy's SKILL.md and compares:

OK DUP DRIFT
StatusMeaningAction
OKOne copy, or multiple identical copiesNothing
DUPMultiple copies, identical content - consistently installed everywhereNothing, or consolidate
DRIFTCopies disagree - different content under the same namePick the source of truth, sync the rest

DRIFT is the signal that matters. It means an update landed in one harness but not another, so you are running two different versions of the same skill depending on which agent you ask.

repoClean: for skills in the repo location, Skill Manager also compares the on-disk file against git HEAD - so an uncommitted edit or a stale checkout shows up too.

07Troubleshooting

Port already in use? - set SM_PORT to another port.
Skills not showing? - check the scan paths exist (the defaults are in the table above). Override with the env vars if your layout differs.
Nothing marked DRIFT? - good. That is the healthy state.
Dashboard stuck on "scanning..."? - the first scan can take a few seconds on large setups; hit Re-scan if it never lands.
